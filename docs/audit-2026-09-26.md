## 2. Constats majeurs

### 2.1 Un socle dominant, copié-collé à la main, qui a dérivé en 8 variantes

Le pattern « Gestion de l'État sur Disque » (4 fichiers : `feature_list.json`, `contract.md`, `progress.md`, `log.md`) apparaît dans **11 dépôts** (+ 1 traduction anglaise dans Trading-AI). C'est la base commune naturelle — mais chaque copie a dérivé :

| Aspect | Variantes constatées | Fichiers |
|---|---|---|
| Rotation du log | mensuelle + découpe par taille ~150 Ko / mensuelle seule / aucune / remplacée par DuckDB / rotation à 400 lignes | L'HERITIER, roblox, video-analys-ia / Laya, YouTubeToMP3 / web-assets / graph-orchestrator / jardin-os |
| Localisation | racine / `.agents/` / `memory-bank/` | 8 dépôts / jardin-os / Trading-AI |
| feature_list | « actives seulement + archive » (récent) vs « cartographie complète » (ancien) | 7 vs web-assets |
| Statuts | `pending\|in_progress\|completed` vs + `awaiting_playtest` | tous vs roblox |
| Budget contexte | ~200 cars/entrée mentionné ou non | roblox vs autres |
| Gate avant sync | verrou statique bloquant (roblox §3.5) absent ailleurs | roblox seul |

Aucun mécanisme de resynchronisation : chaque amélioration (rotation, budget, gate) doit être recopiée à la main — et ne l'est pas.

### 2.2 Doublons exacts et fichiers corrompus

- **3 copies octet-identiques** (`Laya`, `YouTubeToMP3`, `video-analys-ia_sauvegarde…`) et **2 copies octet-identiques** (`disk-clean`, `compare-graph-generator`).
- **3 fichiers au markdown corrompu** (`blender-ia`, `disk-clean`, `compare-graph-generator`) : échappements `\#`, `\*\*`, `&#x20;` et lignes vides doublées typiques d'un export éditeur riche. Rendus illisibles pour un agent, ils perdent tout le balisage (titres, gras, blocs de code).

### 2.3 Aucune structure commune

Ordre des sections, titres, niveaux de détail et langue varient sans logique. Quatre bons modèles coexistent (Trading-AI, jardin-os, ComfyUI, my-claw) mais aucun n'a été réutilisé comme référence.

### 2.4 Redondances inter-dépôts qui vont se désynchroniser

- La cartographie écosystème est décrite **deux fois** (ai-doc2video §« Écosystème », daté 23/09, et generator-assets §« Dépôts consommateurs », daté 15/09 — déjà en retard d'un dépôt `news-editorial-agent`).
- Les règles transversales (secrets, jamais `main` direct, jamais `reset --hard`, zéro extinction machine, validation humaine avant publication) sont réécrites dans 4-5 fichiers avec des formulations différentes.

### 2.5 Fichiers générés / tiers à exclure de la normalisation

- 4 fichiers OpenSpec (2 racines + 2 `openspec/`) : blocs gérés par la CLI → se resynchroniser via `openspec update`, jamais à la main. Les deux `openspec/AGENTS.md` sont de **versions différentes** → mettre à jour.
- 2 blocs auto-gérés Next.js (`fire_UI`, `jardin-os`) : à conserver tels quels.
- `Trading-AI/vendor/timesfm` : dépôt Google vendé.

### 2.6 Tailles extrêmes

De 157 octets (alerte-wti, inutile) à 56 Ko (ai-doc2video — consommé en contexte à **chaque** session). Le détail opérationnel (commandes TTS complètes, protocole OAuth, playlists YouTube) devrait vivre dans des docs référencées, pas dans AGENTS.md.

### 2.7 Contradictions locales à clarifier (pas des bugs, mais à déclarer proprement)

- `fire_UI` et `Trading-AI` **interdisent** les commandes Unix ; `generator-assets` **impose** Git Bash. Légitime par dépôt, mais l'environnement doit être une section déclarée, pas des interdits dispersés.

## 3. Ce qui mérite d'entrer dans la base commune (briques validées)

En parcourant les 24 fichiers, ces règles transversales reviennent et ont fait leurs preuves :

1. **État sur disque = source de vérité** (4 fichiers, formats stricts, bootstrap/Action/Sync/Erreurs) — version consolidée : rotation mensuelle + par taille, « actives seulement + archive », budget ~200 cars/entrée (roblox, L'HERITIER).
2. **Gate avant synchronisation** : une vérification statique en échec interdit la mise à jour du ledger (roblox §3.5).
3. **Git** : jamais de travail/push direct sur `main` ; PR soumise → on s'arrête (pas de boucle d'attente) ; jamais `reset --hard` sur un working tree vivant ; push uniquement sur demande explicite.
4. **Suppressions** : jamais effacer états/bases/archives ; avant toute suppression ambiguë, **reformuler la liste** et faire confirmer (leçon generator-assets 2026-09-08 : 4 modèles supprimés au lieu de 0).
5. **Secrets** : rien dans le code, les commits ni l'écran ; env vars uniquement ; ne jamais logger le contenu des messages.
6. **Actions irréversibles/extérieures** (publish, upload, PROD, extinction machine) : validation humaine explicite dans le chat d'abord, artefacts de contrôle générés avant.
7. **Vérité** : « vérifié » = exécuté réellement ou inspecté visuellement, jamais déduit des logs/intentions (blender-ia §4, L'HERITIER).
8. **Documentation** : toute évolution → mettre à jour la doc maintenue du dépôt + les fichiers d'état avant de clore.
9. **Environnement** : section déclarée (Windows ; shell du dépôt ; `uv` pour Python, jamais pip).
10. **Leçons datées** : format `[AAAA-MM-JJ] contexte | règle` — présent partout où ça marche bien.

## 4. Proposition de normalisation

### 4.1 Architecture cible : 2 niveaux + bloc géré

```
<NOM DÉPÔT>/
├── AGENTS.md                     ← bloc COMMUN (géré, resynchronisable) + SPÉCIFIQUE (libre)
├── PROJECT_MEMORY.md (ou docs/)  ← contexte long : architecture, leçons, écosystème
└── (feature_list.json / contract.md / progress.md / log.md — le « ledger »)
```

- Le **commun** est délimité par des marqueurs `<!-- BEGIN:agents-commun vX -->` / `<!-- END -->`, exactement comme font déjà Next.js et OpenSpec dans vos propres dépôts — un simple script peut resynchroniser le bloc sans toucher au spécifique.
- Le **spécifique** plafonné (~150 lignes) : mission, commandes clés, invariants métier, pièges datés, renvois.
- Le **contexte long** sort d'AGENTS.md (objectif : < 20 Ko par fichier, budget contexte).

### 4.2 Décisions à trancher

| Question | Recommandation | Alternatives |

| Où vit le commun ? | 1 fichier canonique dans un dépôt dédié (ex. `C:\GIT\agents-kit`) + copie par dépôt via bloc géré | sous-module git (friction) ; copie pure sans marqueurs (re-dérive) |
