## 2. Main findings

### 2.1 A dominant base, copy-pasted by hand, that drifted into 8 variants

The "On-disk state management" pattern (4 files: `feature_list.json`, `contract.md`, `progress.md`, `log.md`) appears in **11 repositories** (+ 1 English translation in Trading-AI). It is the natural common base — but every copy drifted:

| Aspect | Observed variants | Files |
|---|---|---|
| Log rotation | monthly + ~150 KB size split / monthly only / none / replaced by DuckDB / rotation at 400 lines | L'HERITIER, roblox, video-analys-ia / Laya, YouTubeToMP3 / web-assets / graph-orchestrator / jardin-os |
| Location | root / `.agents/` / `memory-bank/` | 8 repositories / jardin-os / Trading-AI |
| feature_list | "active only + archive" (recent) vs "full map" (old) | 7 vs web-assets |
| Statuses | `pending\|in_progress\|completed` vs + `awaiting_playtest` | all vs roblox |
| Context budget | ~200 characters per entry mentioned or not | roblox vs the others |
| Gate before sync | blocking static lock (roblox §3.5) missing elsewhere | roblox only |

No resync mechanism: every improvement (rotation, budget, gate) has to be copied by hand — and it is not.

### 2.2 Exact duplicates and corrupted files

- **3 byte-identical copies** (`Laya`, `YouTubeToMP3`, `video-analys-ia_sauvegarde…`) and **2 byte-identical copies** (`disk-clean`, `compare-graph-generator`).
- **3 files with corrupted markdown** (`blender-ia`, `disk-clean`, `compare-graph-generator`): `\#`, `\*\*`, `&#x20;` escapes and doubled blank lines typical of a rich-editor export. Unreadable for an agent, they lose all markup (titles, bold, code blocks).

### 2.3 No common structure

Section order, titles, level of detail and language vary without logic. Four good models coexist (Trading-AI, jardin-os, ComfyUI, my-claw) but none was reused as a reference.

### 2.4 Cross-repository redundancies bound to drift apart

- The ecosystem map is described **twice** (ai-doc2video, "Ecosystem" section, dated 23/09, and generator-assets, "Consumer repositories" section, dated 15/09 — already one repository behind: `news-editorial-agent`).
- Cross-cutting rules (secrets, never directly on `main`, never `reset --hard`, no machine shutdown, human approval before publishing) are rewritten in 4-5 files with different wordings.

### 2.5 Generated / third-party files to exclude from normalization

- 4 OpenSpec files (2 roots + 2 `openspec/`): blocks managed by the CLI → resync with `openspec update`, never by hand. The two `openspec/AGENTS.md` are **different versions** → update them.
- 2 self-managed Next.js blocks (`fire_UI`, `jardin-os`): keep them as they are.
- `Trading-AI/vendor/timesfm`: vendored Google repository.

### 2.6 Extreme sizes

From 157 bytes (alerte-wti, useless) to 56 KB (ai-doc2video — consumed as context in **every** session). Operational detail (full TTS commands, OAuth protocol, YouTube playlists) should live in referenced docs, not in AGENTS.md.

### 2.7 Local contradictions to clarify (not bugs, but to be declared properly)

- `fire_UI` and `Trading-AI` **forbid** Unix commands; `generator-assets` **requires** Git Bash. Legitimate per repository, but the environment must be a declared section, not scattered prohibitions.

## 3. What deserves to enter the common base (validated building blocks)

Across the 24 files, these cross-cutting rules come back and have proven themselves:

1. **On-disk state = source of truth** (4 files, strict formats, Bootstrap/Action/Sync/Errors) — consolidated version: monthly + size-based rotation, "active only + archive", ~200-character budget per entry (roblox, L'HERITIER).
2. **Gate before sync**: a failing static check forbids updating the ledger (roblox §3.5).
3. **Git**: never work/push directly on `main`; PR submitted → stop (no waiting loop); never `reset --hard` on a live working tree; push only on explicit request.
4. **Deletions**: never erase states/databases/archives; before any ambiguous deletion, **restate the list** and get confirmation (generator-assets lesson of 2026-09-08: 4 models deleted instead of 0).
5. **Secrets**: nothing in code, commits or on screen; env vars only; never log message content.
6. **Irreversible/external actions** (publish, upload, PROD, machine shutdown): explicit human approval in the chat first, control artifacts generated beforehand.
7. **Truth**: "verified" = actually executed or visually inspected, never inferred from logs/intentions (blender-ia §4, L'HERITIER).
8. **Documentation**: any change → update the repository's maintained docs + state files before closing.
9. **Environment**: declared section (Windows; repository shell; `uv` for Python, never pip).
10. **Dated lessons**: `[YYYY-MM-DD] context | rule` format — present wherever things work well.

## 4. Normalization proposal

### 4.1 Target architecture: 2 levels + managed block

```
<REPO NAME>/
├── AGENTS.md                     ← COMMON block (managed, resyncable) + SPECIFIC part (free)
├── PROJECT_MEMORY.md (or docs/)  ← long context: architecture, lessons, ecosystem
└── (feature_list.json / contract.md / progress.md / log.md — the "ledger")
```

- The **common** part is delimited by `<!-- BEGIN:... vX -->` / `<!-- END -->` markers, exactly as Next.js and OpenSpec already do in your own repositories — a simple script can resync the block without touching the specific part.
- The **specific** part is capped (~150 lines): mission, key commands, business invariants, dated pitfalls, references.
- **Long context** leaves AGENTS.md (goal: < 20 KB per file, context budget).

### 4.2 Decisions to make

| Question | Recommendation | Alternatives |
|---|---|---|
| Where does the common block live? | 1 canonical file in a dedicated repository (e.g. `C:\GIT\agents-kit`) + one copy per repository through a managed block | git submodule (friction); plain copy without markers (drifts again) |
| Language of the common block | French (21/24 files) — *superseded on 2026-09-26: English since v2.0, see `docs/token-measurement-2026-09-26.md`* | bilingual (heavy) |
| Ledger location | Root by default; `.agents/`, `memory-bank/` allowed if declared | enforce a single location (costly migration) |
| DuckDB variant (graph-orchestrator) | Document it as the **official variant B** of the log section (event database instead of a flat file) | bring it back to .md (loss) |
